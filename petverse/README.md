# 펫버스 무지개 공원 (반려동물 커뮤니티 메타버스) · 프로토타입

반려동물의 사진·영상을 모아 두면 접속할 때마다 무작위로 추억을 꺼내 보여 주고,
3D 공원에서 반려동물과 함께 놀고, 이별했을 때 가상 추모식(무지개다리)과 추모 정원으로 기억을 이어 가는 서비스의 **동작하는 1차 프로토타입**입니다.

`index.html` 하나로 실행됩니다. 브라우저로 열면 됩니다 (Three.js는 CDN에서 불러옴).

---

## 1. 지금 들어 있는 기능

| 영역 | 구현 내용 |
|---|---|
| 오늘의 추억 | 접속하면 현재 반려동물의 사진/영상 중 하나를 무작위로 보여 줌 (직전 것과 겹치지 않게). ‘다른 추억 보기’로 계속 넘김 |
| 추억 앨범 | 사진·영상 여러 개 동시 업로드, 한 줄 메모, 삭제(두 번 눌러 확인). 브라우저 IndexedDB에 원본 저장 |
| 3D 공원 | 탭/클릭으로 이동, WASD·방향키 이동, 휠 줌. 공원 액자 6개에 내 사진·영상이 무작위로 걸림(영상은 자동 재생), 액자를 누르면 크게 보기 |
| 함께 놀기 | 공 던지기(달려가서 물어 옴) · 간식 주기(점프) · 쓰다듬기(멀면 불러옴) · 앉아. 행복도 게이지 |
| 반려동물 | 여러 마리 등록, 종류(강아지/고양이/토끼) · 털 색 · 생일. 종류별로 다른 3D 모델 |
| 무지개다리 추모식 | 떠난 날·추모비 문구·마지막 편지 작성 → 확인 단계 → 4단계 의식(촛불 → 헌화 → 편지 낭독 → 배웅). 반려동물이 무지개를 오르다 별이 되어 하늘에 자리 잡음 |
| 추모 정원 | 추모비(이름·생몰일·문구), 꺼지지 않는 촛불, 헌화 누적, 하늘의 별. 정원에 들어가면 하늘이 저녁빛으로 바뀜 |
| 추모 이후 | ‘별이 된 친구’는 반투명하게 빛나는 모습으로 공원에서 계속 함께 걸음. 방명록, 별이 된 지 N일 · 다음 기일까지 N일 표시 |
| 예시 데이터 | 처음 열면 예시 반려동물 ‘콩이’와 예시 사진 3장이 들어 있음(‘예시’ 표시, 한 번에 삭제 가능) |

### 지금 프로토타입의 한계 (정확히)
- **데이터는 그 기기의 그 브라우저에만 저장**됩니다. 다른 기기 동기화, 다른 사용자와의 공유, 멀티플레이(다른 사람 아바타가 보이는 것)는 **아직 없습니다** → 서버가 필요합니다(아래 2장).
- 브라우저 저장 공간에는 한도가 있어 영상을 많이 올리면 저장이 실패할 수 있습니다(한도는 브라우저·기기 여유 공간에 따라 다름). 파일 하나는 300MB로 제한했습니다.
- 3D 모델은 기본 도형으로 만든 캐릭터입니다. 실제 내 반려동물처럼 보이게 하는 것은 다음 단계 과제입니다.

## 2. 실제 서비스로 만들 때의 구조 (권장안)

```
[웹/앱 클라이언트]  React + React Three Fiber(웹) / 필요 시 Unity
        │  REST/GraphQL                │ WebSocket
        ▼                              ▼
[API 서버] 인증·반려동물·앨범·추모관   [실시간 서버] Colyseus 방 단위 동기화
        │                              (공원·추모식 같이 보기)
        ▼
[DB] PostgreSQL (Supabase 등)   [파일] S3 / Cloudflare R2 + CDN
        │
[작업 큐] 썸네일·리사이즈·영상 트랜스코딩(ffmpeg 워커 또는 관리형 서비스), 유해물 검수
```

- **업로드**: 서버가 발급한 서명 URL(presigned URL)로 클라이언트가 저장소에 직접 업로드 → 서버 트래픽·비용 절감.
- **랜덤 추억**: “오늘의 추억”은 서버에서 날짜 시드 기반으로 고르면 같은 날엔 가족 모두가 같은 추억을 보게 할 수 있음(공유 경험). “N년 전 오늘” 우선 노출도 가능.
- **멀티플레이**: 처음부터 MMO처럼 만들지 말고, ‘방(최대 10~20명)’ 단위로 시작. 추모식에 가족·친구를 초대하는 “함께 보기”가 가장 가치가 큰 멀티 기능.
- **반려동물 닮은 3D**: 사진 몇 장 → 비전 AI로 종·털 색·무늬·귀 모양 추출 → 파라메트릭 모델에 적용하는 방식이 현실적. 사진→완전한 3D 재구성은 품질·비용 편차가 커서 2단계로 미루는 것을 권장.

## 3. 꼭 짚어야 할 법·윤리 이슈 (한국 기준)

- **동물장묘업**: 동물보호법상 동물장묘업은 사체를 실제로 처리하는 영업(장례·화장 등)으로 등록 대상입니다. 이 서비스의 *가상* 추모식 자체는 사체를 다루지 않으므로 그 등록 대상은 아니라고 보지만, **실제 장례 예약·연계·중개를 붙이면 반드시 등록된 업체와만 제휴**해야 합니다(등록 업체는 농림축산식품부 동물보호관리시스템에서 확인 가능). 사업화 전 변호사 확인을 권합니다.
- **개인정보·사진**: 회원 정보, 위치 정보가 담긴 사진 EXIF, 사진 속 사람 얼굴 → 개인정보보호법 대상. 업로드 시 EXIF 위치 정보 제거를 기본값으로.
- **커뮤니티 운영**: 공개 게시·댓글이 생기면 신고·차단·삭제 절차와 유해물 필터가 필요합니다.
- **슬픔을 다루는 UX**: 추모 이후 반려동물을 계속 보여 줄지, 알림(기일 등)을 받을지는 **사용자가 고를 수 있게** 해야 합니다. 지금 프로토타입도 강제 진행 없이 확인 단계와 ‘그만두기’를 넣었습니다.

## 4. 수익 모델 후보

1. **저장 용량 구독**: 무료 n GB → 유료로 고화질 원본·영상 무제한 보관. (추억 보관은 해지 이탈이 낮은 편이라 구독과 잘 맞음)
2. **영구 추모관 패키지**: 추모 정원 꾸미기, 추모 영상 자동 제작, 가족 초대 추모식.
3. **B2B 제휴**: 등록된 반려동물 장례식장이 고객에게 ‘온라인 추모관’을 제공하도록 화이트라벨 공급.
4. **꾸미기 아이템**: 반려동물 옷·장난감·공원 소품 (확률형 아이템은 피하는 것을 권장).
