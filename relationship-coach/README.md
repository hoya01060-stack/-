# 말결 — 관계 대화 분석·코칭 모바일 웹 MVP

> “이 말, 어떻게 받아들여야 할까요?”
> 대화 속 근거와 가능한 해석을 살펴보고, 나에게 맞는 다음 말을 찾아보세요.

연애·부부·가족·친구·직장 등 모든 인간관계의 대화를 대상으로 하는 한국어 코칭 도구입니다.
**상대의 속마음을 확정하지 않습니다.** 대화에 실제로 있는 말(관찰)과 그에 대한 가능한 해석, 사용자가 고를 수 있는 대응(제안)을 구분해서 보여 줍니다.

“말결”은 임시 이름입니다. 이 폴더는 저장소 루트의 주식 알림 봇(Python)과 독립된 Next.js 프로젝트입니다.

---

## 1. 실행 방법

필요 환경: Node.js 20 이상(22에서 검증), npm.

```bash
cd relationship-coach
npm install
cp .env.example .env.local   # 키를 비워 두면 데모 모드
npm run dev                  # http://localhost:3000
```

운영 빌드:

```bash
npm run build
npm start
```

검증 명령:

| 명령 | 내용 |
|---|---|
| `npm run typecheck` | TypeScript 타입 검사 |
| `npm test` | 핵심 동작 단위·API 테스트(Vitest, 42개) |
| `npm run build` | 운영 빌드 |
| `npm run test:e2e` | 빌드 결과를 띄워 모바일 화면(375×812) 전체 흐름 점검(Chromium, 62개 항목). 먼저 `npm run build` 필요. 스크린샷은 `e2e/screenshots/`에 저장 |

E2E는 `playwright-core`로 이미 설치된 Chromium을 사용합니다. 경로가 다르면 `CHROMIUM_PATH=/path/to/chrome npm run test:e2e`.

## 2. 환경변수

모두 **서버 전용**입니다. `NEXT_PUBLIC_` 접두사를 쓰지 않으므로 브라우저 번들에 들어가지 않습니다.

| 변수 | 기본값 | 설명 |
|---|---|---|
| `AI_PROVIDER` | `anthropic` | AI 제공사. `demo`로 두면 키가 있어도 데모 모드 |
| `AI_MODEL` | `claude-opus-5-5` | 사용할 모델 ID |
| `ANTHROPIC_API_KEY` | (없음) | 비어 있으면 **데모 모드**로 실행 |
| `AI_TIMEOUT_MS` | `60000` | AI 호출 시간 제한 |
| `AI_FALLBACKS` | (켜짐) | `off`면 Anthropic 서버 측 거절 시 대체 모델 재시도(`fallbacks: "default"`)를 끔 |
| `RATE_LIMIT_MAX` | `8` | IP당 분석 요청 허용 횟수(답장 재생성은 2배) |
| `RATE_LIMIT_WINDOW_MS` | `600000` | 요청 제한 창(10분) |

### AI 제공사 교체

`src/lib/ai/types.ts`의 `AIProvider` 인터페이스(`generateJSON`)를 구현하고 `src/lib/ai/registry.ts`에 등록하면 됩니다. 프롬프트·근거 검증·원칙 필터는 제공사와 무관하게 동일하게 적용됩니다. 현재 구현된 실제 제공사는 Anthropic 하나이며, Anthropic 호출은 구조화 출력(JSON Schema)과 `effort: "medium"`을 사용합니다.

## 3. 사용자 흐름

홈 → ① 관계·목표 선택 → ② 상황·대화 입력 → ③ 발화자 확인 → ④ 전송 내용 확인(개인정보 가림·미리보기) → ⑤ 맥락 질문·말투 → 분석 결과 → 답장 수정·복사

- 어느 단계에서든 이전으로 돌아가 입력을 고칠 수 있고, 오류·정보 부족 시에도 입력은 지워지지 않습니다.
- 전송 내용에 영향을 주는 값(대화, 발화자, 가림 설정)이 바뀌면 “확인했습니다” 체크를 다시 받습니다.
- 상단 **기록 삭제**는 확인 후 세션의 모든 입력·결과를 메모리에서 지우고 처음으로 돌아갑니다.

| 신고 | 사유만 전송(원문·결과·자유 의견은 받지 않음, 추가 필드가 있으면 거절) |
| 남용 방지 | 본문 64KB·상황 1,500자·대화 8,000자·메시지 200개·메시지당 1,000자 제한, IP별 요청 제한(429 + Retry-After), requestId 기반 중복 제출 차단(409) + 화면 연타 방지 |
| 접근성 | 의미 있는 제목 구조, 단계 전환 시 제목 포커스 이동, 네이티브 라디오·체크박스(화살표 키), `<dialog>`(Esc), `aria-live` 로딩·오류 알림, 44~48px 터치 영역, 포커스 표시, 동작 줄이기 설정 존중 |
| 화면 상태 | 로딩(스켈레톤), 오류(코드·재시도), 빈 화면(대화 없음·근거 없음·답장 없음) |

## 5. 분석 원칙을 코드로 강제하는 방법

프롬프트(`src/lib/prompt.ts`)로 원칙을 지시하지만, 모델이 따르지 않을 수 있으므로 **서버 후처리(`src/lib/postprocess.ts`)가 최종 결과를 다시 거릅니다.**

1. **원문 근거 검증** — 모든 인용을 전송된 메시지 원문과 글자 단위로 대조(공백·따옴표 정규화만 허용). 없으면 제외하고 개수를 화면에 표시. 발화자는 모델 출력이 아니라 원문에서 가져옴. 검증된 근거가 없는 관찰·해석은 결과에서 뺌.
2. **점수·확률 금지** — “호감도 70%”, “관심도가 높다” 등 수치화 문장 제거.
3. **진단 금지** — 성격장애·정신질환·애착 유형 라벨이 들어간 문장 제거.
4. **편들기·단정 제한** — “당신 말이 전적으로 맞다”, “상대는 분명히 당신을 좋아한다” 같은 문장 제거.
5. **조종·감시·보복 금지** — 질투 유발, 일부러 답장 늦추기, 몰래 확인·위치 추적, 복수 등을 담은 선택지·답장은 통째로 제외.
6. **위험 상황** — 입력의 위협·폭력·스토킹·자해 신호(키워드) 또는 맥락 질문의 “안전 걱정 있음”이면 위험 모드: 112·1366(·자해 시 109) 안내, “안전을 먼저 확보하기” 선택지 추가, 직접 만나기·찾아가기·화해 권유 제거(“만나지 않겠다” 같은 부정문은 유지).
7. **입력 속 명령문 방어** — 사용자 자료는 system이 아닌 user 메시지의 `<data>` 안에 JSON 문자열로만 들어가며 `<`를 이스케이프해 경계를 깰 수 없음. 명령처럼 보이는 문장은 감지해 모델에 “자료로만 취급” 경고를 붙이고 화면에 알림. 명령을 따른 출력도 위 1~5에서 걸러짐.
8. **힘의 차이·감정 분리** — 맥락 질문으로 수집해 프롬프트에 전달(이 부분은 코드 필터가 아닌 프롬프트 지시).

> 한계: 2~7의 필터는 정규식 기반이라 표현을 바꾼 위반을 놓치거나, 정상 문장을 과하게 지울 수 있습니다. 편들기·감정/의도 분리처럼 의미 판단이 필요한 원칙은 프롬프트에 의존합니다. 실제 키로 품질을 평가하는 과정(평가 세트)이 공개 전에 필요합니다.

## 6. 데모 모드와 실제 분석의 차이

| | 데모 모드 (키 없음) | 실제 분석 모드 |
|---|---|---|
| 서버로 보내는 내용 | 관계·목표·말투·고른 사례 ID만. **대화·상황·맥락 답변은 보내지 않음** | 가림 처리된 상황·대화(역할만)·맥락 답변 |
| 결과 | 미리 작성한 **가상 사례 5종**(직장·연애·가족·자료 부족·안전)의 예시 출력 | AI가 입력을 분석한 출력 |
| 검증 | 실제와 같은 후처리를 통과(일부 사례는 가짜 인용·대면 권유를 일부러 넣어 걸러지는 모습을 보여 줌) | 동일 |
| 표시 | 상단 “데모” 배지, 결과에 “입력하신 대화를 분석한 것이 아닙니다” 안내와 사용된 가상 대화 표시 | 외부 AI 제공사로 전송된다는 안내 |

데모 결과는 실제 AI 출력이 아니며, 실제 분석의 품질을 보장하지 않습니다.

## 7. 개인정보 처리 방식(현재)

- 원문·결과를 데이터베이스, localStorage/sessionStorage, 쿠키, 분석 도구에 저장하지 않습니다. 화면 상태(React 메모리)에만 있고 기록 삭제·새로고침·창 닫기로 사라집니다. (E2E에서 저장소·쿠키가 비어 있음을 확인)
- 서버 로그에는 오류 코드와 숫자만 남기며 요청 본문·AI 응답·오류 객체를 기록하지 않습니다. (테스트로 확인)
- 응답 헤더: `Cache-Control: no-store`(API), CSP(`connect-src 'self'`, 외부 스크립트 없음), `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY` 등.
- 실제 분석 시 가림 처리된 내용이 **외부 AI 제공사(Anthropic)로 전송**됩니다. 제공사의 처리·보존 조건은 그 제공사의 정책을 따르므로, 이 서비스는 “완전 무저장”을 보장한다고 표시하지 않습니다.
- 요청 제한을 위해 IP 주소를 서버 메모리에 최대 10분 보관합니다(디스크 저장 없음).
- 복사한 답장은 기기 클립보드에 남을 수 있음을 초기화 화면에서 안내합니다.

## 8. 공개 서비스 전에 추가해야 할 보안·개인정보 항목

**법·정책**
- [ ] 개인정보 처리방침·이용약관 작성(수집 항목, 국외 이전 — AI 제공사 서버 위치, 보존 기간, 제3자 제공). 개인정보보호법상 **국외 이전 고지·동의**와 **제3자(대화 상대방) 정보** 처리 근거 검토(법률 자문 권장)
- [ ] AI 제공사와의 데이터 처리 계약(DPA) 및 보존·학습 미사용 조건 확인. 필요 시 무보존(ZDR) 등 조건 협의
- [ ] 만 14세 미만 이용 제한 또는 법정대리인 동의 절차
- [ ] 위기 상황 안내 문구·연락처의 전문가 검토 및 정기 갱신

**보안**
- [ ] 다중 인스턴스 배포 시 요청 제한·중복 제출 방지를 Redis 등 공유 저장소로 이전(현재는 단일 프로세스 메모리)
- [ ] 신뢰할 수 있는 프록시가 넣은 IP 헤더만 사용하도록 설정(현재 `x-forwarded-for` 첫 값을 그대로 신뢰 → 위조로 제한 우회 가능)
- [ ] 봇 방어(CAPTCHA 등)와 계정·세션 단위 사용량 제한, AI 비용 상한 경보
- [ ] CSP에서 `'unsafe-inline'` 제거(nonce 기반), HSTS 적용, 의존성 취약점 정기 점검(`npm audit`)
- [ ] API 키 보관을 비밀 관리 서비스로 이전, 키 교체 절차 마련
- [ ] 호스팅·CDN·리버스 프록시의 **요청 본문 로깅이 꺼져 있는지** 확인(애플리케이션 밖 로그에 원문이 남을 수 있음)
- [ ] 오류 모니터링 도입 시 요청 본문·브라우저 입력값 수집을 끄는 설정(예: breadcrumb/입력 캡처 비활성화)

**품질·안전**
- [ ] 실제 키로 평가 세트를 만들어 인용 정확도, 판단 보류 적절성, 편들기·진단·위험 상황 처리를 측정(정규식 필터의 누락·과잉 측정 포함)
- [ ] 위험 신호 감지를 키워드 외 방식(분류 모델 등)으로 보강하고 전문가 검수
- [ ] 개인정보 가림 보강(이름·별명·회사명 등 고유명사 인식), 가림 누락 신고 경로
- [ ] 신고 내용 검토 운영 프로세스(현재 신고는 사유별 개수만 메모리에 집계되고 재시작 시 사라짐)
- [ ] 다크 모드·스크린 리더(VoiceOver/TalkBack) 실기기 점검

## 9. 범위에서 제외한 것

이미지·음성 입력, 카카오톡 자동 연동, 결제, 전문가 연결, 대화·결과 영구 저장, 외부 배포.

## 10. 코드 구조

```
src/
  app/                 Next.js App Router (페이지, API 라우트: analyze·reply·report·config)
  components/          화면(단계별 steps/, 결과 result/)
  lib/
    service.ts         API 처리(크기·요청 제한, 중복 제출, 데모/실제 분기, 오류 매핑)
    postprocess.ts     근거 검증·원칙 필터
```
